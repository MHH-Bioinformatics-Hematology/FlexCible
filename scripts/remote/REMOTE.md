## Batch size: use the wrapper

train.batch_size is per rank (3), the local DDP runs use 2 ranks, global batch 6. On one GPU
scripts/run_single_gpu.py multiplies the batch size of every generated config by
HICMULTI_BATCH_SCALE (default 2), so the optimizer steps per epoch, learning rate and early
stopping equal the local recipe. HICMULTI_BATCH_SCALE=1 keeps global batch 3 (a different recipe,
not comparable).

## Run one job

A job from the multicell_expanded family (output folder runs/multicell_reference/<run>, log
<run>.log next to it, cache from cache_expanded; the cache must exist, check
`ls $HM/cache_expanded/<cache>/manifest.json`):

    RUN=all12honest_drop_meth ; RES=25000 ; NAME=all12honest_drop_meth_25kb
    HM=/mnt/processed/wolffjoa/hic-multiome
    python scripts/claim_job.py claim $NAME --done-path $HM/runs/multicell_reference/$NAME/best \
        --cmd "run_single_gpu $RUN $RES" || exit 0          # exit 1 or 2: claimed elsewhere or finished
    python scripts/run_single_gpu.py multicell_expanded --runs $RUN --res $RES --stage train --gpus 0 \
        > $HM/runs/multicell_reference/$NAME.remote.out 2>&1 \
        || python scripts/claim_job.py release $NAME

`--gpus 0` makes multicell_expanded call `torchrun --standalone --nproc_per_node=1 -m
hicmultiome.train --config <run>.yaml`. The same step by hand:

    torchrun --standalone --nproc_per_node=1 -m hicmultiome.train --config <config.yaml>

The yaml is written by the stage into the output folder on the share; any other config
(configs/*.yaml, configs/scenario/*.yaml) can be passed directly. A config is pointed at its
data with absolute paths (cool_path, bigwig_dir, cache_dir, output_dir): edit them or generate
the yaml through the stage, never edit a config of a running job.

Scenario-benchmark dedicated trainings (output runs/scenario_bench/<run>, config in
configs/scenario/<run>.yaml, regenerated by --stage configs):

    python scripts/run_single_gpu.py scenario_bench --stage configs      # writes only configs/scenario in THIS repo copy
    python scripts/claim_job.py claim scen_ctcf_meth_25kb_s1 \
        --done-path $HM/runs/scenario_bench/scen_ctcf_meth_25kb_s1/best || exit 0
    python scripts/run_single_gpu.py scenario_bench --stage train --run scen_ctcf_meth_25kb_s1 --gpus 0

Inference-only scoring and evaluation (--stage eval of multicell_expanded, scenario_bench --stage
dedicated/infer) use `--gpu 0` / `CUDA_VISIBLE_DEVICES=0` and run one process per GPU.

Outputs land directly in the share: runs/multicell_reference/<run>*, runs/scenario_bench/<run>*,
logs next to them. Nothing is written to the local disk except configs/scenario in this repo
copy and ~/scratch (2 kb staging).

## Claim convention (both machines write to runs/multicell_reference)

A job is claimed before it starts. Claims live in $HM/runs/multicell_reference/claims/:

- `<run>.claim`: the arbiter, created with O_CREAT|O_EXCL by scripts/claim_job.py (the SMB server
  refuses the second create, so exactly one machine wins even when both start in the same second;
  tested from both machines on throwaway names, 20 simultaneous names, 20 of 20 single winners).
  Content: JSON with host, pid, time and the command.
- `<run>.claimed_by_<host>`: the visible marker, created by the winner.

Rules for both queues:
1. Before starting a training: `python scripts/claim_job.py claim <run> --done-path <run folder>/best`.
   Exit 0 start, 1 skip (claimed by the other machine), 2 skip (finished).
2. A claim is never removed on success. A failed or killed job is released by its owner
   (`claim_job.py release <run>`); a claim of a dead job is removed by hand after looking at the log.
3. `claim_job.py list` shows all claims, `status <run>` one claim.
4. Run names are the claim keys (all12honest_drop_meth_25kb_s1, scen_meth_only_25kb_s0, ...), the
   same string on both machines.
The local scheduler and gpu_queue_extra.py do not call claim_job.py (not wired in). Until they
do, the safe division is by disjoint job lists: this machine runs only the jobs assigned in the
split proposal, and the local queue reaches them later than this machine finishes them (the local
queue then skips them, because dedicated_done() sees the finished run on the share).

## Runners added 2026-10-10 (all started with `setsid nohup ~/hicenv/bin/python <file> > <file>.out 2>&1 &` in ~/hic-multiome-unet)

- aml_prep.py: CPU preparation (references, caches, hard split) of the AML folds 10, 11, 12 (registry 52).
- remote_queue_aml.py (PID file remote_queue_aml.pid): waits for the CNN and the earlier runners, 60-step smoke, then per fold the
  trainings all12aml_{refin,honest}_drop_f<N> at 25 and 10 kb and `aml_train_eval.py --fold N` (HICMULTI_GPUS=0), results copied to
  runs/aml_train_remote/fold<N>/. Done marker REMOTE_QUEUE_AML_DONE in remote_queue.log.
- remote_queue_cohesin.py (PID file remote_queue_cohesin.pid): waits for remote_queue_aml.py (PID file gone and done marker, or all
  AML jobs finished or claimed), the CNN and 2 quiet GPU minutes; 60-step smoke on the 25 kb config; then all12cohfix_refres_drop 25 kb,
  10 kb, all12cohfixna_refres_drop 25 kb, 10 kb (each train then `--stage eval`; a job whose cache manifest or operator is missing is
  retried after the others), then the CPU prediction stages perturb_validate predict/predict_chip, washout predict, aml_eval predict on
  the share (scoring stays on the local machine). Done marker REMOTE_QUEUE_COHESIN_DONE.
All runners log to remote_queue.log, claim jobs by run name in runs/multicell_reference/claims/ and stop after 2 consecutive failures.
Stop one with `kill $(cat <runner>.pid)`.

- remote_queue_more.py (PID file remote_queue_more.pid, 2026-10-11): 60-step smoke on the first B config; A caches (meth AML
  folds 10 to 12) precomputed in the background at nice 10 with 8 workers; B = honest seed replicates (seeds 1 and 2) of
  all12refin_drop, all12refres_drop, all12honest_drop at 25 and 10 kb with `--stage eval` after each; then A = per fold
  all12aml_meth_refin_drop_fN 25 and 10 kb, all12aml_refres_drop_fN 10 kb and `aml_train_eval.py --fold N --variant extra`
  (results eval_fN_extra_*.csv copied to runs/aml_train_remote/fold<N>/). Claims by run name (the local queue takes the same
  B jobs through the same claims). Done marker REMOTE_QUEUE_MORE_DONE.
